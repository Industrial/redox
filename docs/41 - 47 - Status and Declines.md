# Plan 47 — Status and Declines

Plan ID: `status-and-declines`
Depends on: 44 (`zero-cost-benchmarks`)
Milestone: 7 — *tooling*
Status: `done` 2026-11-10

---

## 1. What this plan is

Two documents, and they are opposites. `docs/STATUS.md` says what is true and is **measured**;
`docs/DECLINED.md` says what will never be true and is **judged**. Both are the posture doc 02
names from Emerald's README — *"none of this is rounded up"* — and the whole value of either
is that a reader can trust it without reading the code.

Which is exactly why the previous row's lesson applies: plan 46 §1.3 found that **two thirds
of a careless inventory was wrong**, and the fix was to make a machine resolve every claim. A
status document is worse than that inventory, because its numbers go stale on every commit
rather than on every surface change.

So **`STATUS.md` is generated and blessable**, not written. §1.2.

### 1.1 Verified preconditions

Measured 2026-11-10. Every number below is what a generator would produce, and each was
cheap — the whole set computes in under a second from the working tree.

| Measure | Value |
|---|---|
| Rust source, `crates/*/src` | **24,159** lines across 11 crates |
| Integration tests, `crates/*/tests` | 11,103 lines |
| Largest crate | `redox-parser` at 6,325 |
| Smallest | `redox-fuzz` at 120 |
| `examples/*.sdx` | 29 |
| `tests/golden/*.xrs` | 28 |
| `crates/redox-cli/tests/ui/*.sdx` | 28 |
| `tests/unreachable/*.sdx` | 6 |
| `benchmarks/pairs/*.sdx` | 9 |
| Diagnostic codes declared | 24 |
| `UNREACHABLE` rows in `docs/GRAMMAR.md` | 6 |
| Declines in doc 03 §22 | 17 |

**29 examples and 28 goldens is not an error.** `examples/lexical.sdx` deliberately does not
parse — it is the error-path example, and `benchmarks/REPORT.md` already excludes it from the
throughput sweep for the same reason. A status document that quietly reported "29 examples,
all green" would be rounding up by exactly one file, which is the failure mode this row exists
to prevent, so the number is stated **with** its exception.

Two measurements were wrong on the first attempt and are worth recording because they are the
kind a hand-written document would enshrine: the diagnostic count came out as **2** from a
grep for `"RDX[0-9]{4}"` string literals (the codes are generated from variant names, so only
two appear as literals — in a doc comment and a test), and the `UNREACHABLE` count came out as
**7** because the grep caught the legend row explaining what the grade means. The real numbers
are 24 and 6.

### 1.2 `STATUS.md` is a blessable golden, not prose

This repository already has the right idiom for a measured artifact, three times over:
`tests/golden/*.xrs`, `tests/ui/*.stderr` and `examples/*.stdout` are all generated,
committed, and compared in the gate, with `REDOX_BLESS=1` rewriting them and then **failing**
so the diff is reviewed rather than absorbed.

`STATUS.md` takes the same shape. The gate recomputes the numbers and compares; a drifted
document fails the build, and `REDOX_BLESS=1 cargo test -p redox-cli --test status` rewrites
it.

Three consequences, all wanted:

- **The numbers cannot rot.** A plan that adds a crate or an example updates the document in
  the same commit, because otherwise its own gate fails.
- **The diff is the changelog.** A reviewer sees "parser +300 lines, examples +1" in the
  commit that caused it.
- **Prose and measurement are separated by construction.** Anything a generator cannot compute
  does not belong in `STATUS.md`; it belongs in the plan that decided it.

Plan 44's `benchmarks/REPORT.md` is the near precedent and the instructive difference: it is
generated by `cargo run -p redox-bench` and **not** compared in the gate, because its numbers
are timings and would flake. `STATUS.md`'s numbers are counts, so they can be compared
exactly, and anything that cannot be is not in it.

### 1.3 The gap table is derived, not written

Row 47's cell asks for *"a visible gap table"*. Plan 46 built the inventory that knows the
gaps, and a second hand-written list beside it would disagree within one row.

So `STATUS.md`'s gap table is **read out of `docs/GRAMMAR.md`** — every row graded
`UNREACHABLE`, with its fixture. One source of truth, and the fixtures are already asserted to
still fail (plan 46 §3 criterion 3), so a closed gap updates both documents from one edit.

This is the dependency between the two rows doing real work rather than being declared.

### 1.4 `DECLINED.md` is judged, and doc 03 §22 is its source

A decline is not a measurement. It is a decision with a reason, and the reason is the whole
artifact — *"no Rust lowering target exists"* is useful where *"not supported"* is not.

Doc 03 §22 holds 17 of them and is the source. `DECLINED.md` restates them for a reader who
has not read a 2,000-line surface document, and a test asserts **every §22 construct appears**,
so the two cannot drift.

**One finding already.** Two rows of §22 give their reason as *"duplicates `with` (§7.5)"* —
Cascades, and scope functions (`apply`, `tap`, `doto`). Doc 18 §7 **deleted** doc 03 §7.5's
`with` blocks and reused the keyword for doc 30 §3.3's callback bind. So those two declines
cite a construct that no longer exists.

The declines still stand; their stated reason does not. §5 criterion 6 fixes the reason rather
than the verdict, because the verdict was never about the keyword — it is that both forms are
method-chaining sugar with no Rust lowering of their own.

### 1.5 What `STATUS.md` must not claim

The posture doc 02 takes from Emerald is *"none of this is rounded up"*, and the honest version
of that is a document that states what it does **not** know:

- **Test counts are not a quality measure**, and the document says so rather than printing a
  number next to a tick.
- **"Done" is a register status, not a guarantee.** 42 rows of doc 04 read `done`; four of them
  have recorded a later row finding something they got wrong, and the document links the
  register rather than summarising it.
- **Coverage is absent on purpose.** `moon run :coverage` exists; a percentage in a status
  document invites optimising the percentage. §6.

## 3. Concrete proof this plan targets

```bash
moon run :test                                        # both documents are current
REDOX_BLESS=1 cargo test -p redox-cli --test status   # rewrite STATUS.md, then review the diff
```

The gate asserts:

1. `docs/STATUS.md` equals what the generator produces from the working tree.
2. Its gap table lists exactly the `UNREACHABLE` rows of `docs/GRAMMAR.md`.
3. `docs/DECLINED.md` names every construct in doc 03 §22.

Criterion 2 is what makes the dependency on plan 46 real: the two documents are checked against
each other, so neither can be the stale one.

## 5. Acceptance criteria

1. `docs/STATUS.md` exists, carries §1.1's measures, and is **regenerated and compared** by the
   ordinary gate.
2. `REDOX_BLESS=1` rewrites it and then fails, so a changed number is reviewed.
3. Its gap table is derived from `docs/GRAMMAR.md`'s `UNREACHABLE` rows and matches them
   exactly.
4. The 29-examples-28-goldens difference is stated **with** its reason, not smoothed over.
5. `docs/DECLINED.md` carries all 17 of doc 03 §22's declines with their reasons, and the two
   entries with a named venue are marked as reopenable rather than permanent.
6. §22's two *"duplicates `with` (§7.5)"* reasons are **corrected** — the construct they cite
   was deleted by doc 18 §7.
7. No coverage percentage, and no test count presented as a quality measure (§1.5).

## 6. Out of scope, and what it discloses

- **A coverage percentage.** `moon run :coverage` produces one; putting it in a status document
  makes it a target, and the number it would report is dominated by the emitter's match arms
  rather than by anything a reader cares about.
- **Per-plan status detail.** Doc 04 is the register and is 50 rows of recorded fact.
  `STATUS.md` links it and counts it; duplicating it would create a second register free to
  disagree.
- **A roadmap or dates.** What is left is doc 04's remaining rows; when they land is not a
  measurement and this document only carries measurements.
- **Benchmark numbers.** `benchmarks/REPORT.md` has them and is deliberately not gate-compared
  because they are timings (plan 44 §1.2). Copying a timing into a compared document would make
  the gate flake, which is the specific thing plan 44 refused.
- **A public README.** Doc 02 cites Emerald's README for its *posture*, not as an artifact to
  reproduce. A project-facing README is a different audience and a different row.

## 10. Result

Shipped 2026-11-10. `docs/STATUS.md`, generated and gate-compared by
`crates/redox-cli/tests/status.rs`; `docs/DECLINED.md`, with
`crates/redox-cli/tests/declined.rs` asserting doc 03 §22 ⊆ the document.

§1.2's argument — that a status document must be generated because its numbers go stale on
every commit — was right for a reason better than the one given. It did not just keep the
numbers current. **It found that the previous row's numbers were wrong.**

### 10.1 Counting the same thing twice found a row the inventory could not see

The generator reads its gap table out of `docs/GRAMMAR.md` (§1.3), and its first run produced
**six** gaps where the document visibly grades **seven**. The missing one was `|`
or-patterns.

The cause is one character. That row's *area* cell is `` `|` `` — a literal, unescaped pipe in
a markdown table — so every parser split the row into the wrong cells, found something other
than a grade in the second one, and skipped it. It was graded `UNREACHABLE` in the document,
and it was **invisible to plan 46's own test**: `tests/unreachable/or_pattern.sdx` existed, was
cited, and was never checked. A reader saw seven gaps; the machine enforced six.

So plan 46 §10 is amended — 89 rows and 7 gaps, not 88 and 6 — and both parsers now share a
`split_cells` that honours `\|`.

**The lesson is sharper than plan 46 §1.3's.** That section argued an inventory is only worth
its page if a machine resolves every claim. True, and insufficient: *"a machine checks it"* is
itself a claim, and the only thing that caught this one was **counting the same quantity a
second way, from a different direction, and comparing**. §3 criterion 2 was written to make the
two documents check each other; it found a defect in the first one on its first run.

### 10.2 Two more parser mistakes, both in this row's own generator

Recorded because they are the same class and would each have produced a confidently wrong
document:

- **The plan table said 40 done, 4 superseded, 6 outstanding** — the truth is 42, 4, 4. Rows 2
  and 46 have pipes inside code spans in their *status* text, so the last-cell split landed on
  the wrong cell. Fixed by finding the **last status marker on the line** instead, which no
  number of pipes can disturb.
- **Then the total came out as 54 for a 50-row register.** Doc 04 has a second table — the
  `Plan | Document` index — whose rows open identically with `| NN | `slug` |` and carry no
  status. Fixed by requiring a status, which is what makes a register row a register row.

Three parsing errors in one row, all from the same cause: markdown tables are not a data
format, and this repository stores structured facts in them. Named here rather than hidden
because the next row to read one of these documents will hit it again.

### 10.3 A generator trips the no-literal-expectations check, and should

`no_literal_expectations.rs` failed on `status.rs`: *"embeds program output as a string
literal; put the program beside a .stdout file instead"*. Plan 08 §2.1's rule is that an
expectation must be a **file**, because Emerald's one syntax cutover orphaned 113 fixtures that
lived as string literals in test modules.

The flag is a false positive on the letter and a near miss on the spirit, which is worth being
precise about rather than exempting quietly. This test's **expectation is a file** —
`docs/STATUS.md`, compared byte for byte and blessable, which is exactly the shape the rule
asks for. What the literals hold is the *template*: prose that the generator interpolates
numbers into. The heuristic sees long text inside a string and cannot distinguish a generator
from a captured stdout, and no heuristic reading Rust source could.

So `status.rs` joins `ALLOWED` with that reason, which is the mechanism the list exists for and
the discipline it states — *"an allow with no reason is how a check stops meaning anything"*.
It is the second entry in a list that had one.

The alternative considered and declined: move the prose to `docs/STATUS.template.md` with
placeholders. It would satisfy the heuristic, and it would add a second file that has to stay
in sync with the placeholder names — trading a checked exemption for an unchecked coupling.

### 10.4 The posture, tested once

§1.1 predicted the 29-examples-28-goldens difference would be the first test of whether *"none
of this is rounded up"* means anything. The generator states both numbers and the reason in
the same sentence, so there is no version of the document that reports 29 green examples.

Two of this row's own preconditions were also wrong on the first measurement — 24 diagnostic
codes read as 2, and the gap count as 7 before it was 6 and then 7 again — which is §1.1's
argument for generating rather than typing, made by the row that argued it.

### 10.5 What `DECLINED.md` turned out to be for

The decline/gap distinction (§6, doc 03 §22 versus `docs/GRAMMAR.md`) read as pedantry when
this plan was written. Writing both documents made it load-bearing: **macro definition is in
both**, and it is the only construct in that position — declined by doc 03 §23 item 3 *and*
unreachable. Four other constructs are gaps nobody decided on, and would have read as refusals
if the two lists had been merged.

`DECLINED.md` therefore ends with a *"not declined — merely absent"* section, which is the part
a reader needs and neither source document had.

### 10.6 §22's stale reason, corrected

Criterion 6 landed as written: cascades and scope functions gave their reason as *"duplicates
`with` (§7.5)"*, and doc 18 §7 deleted §7.5's `with` blocks. A reader following the citation
found a deleted section. Both reasons are restated in doc 03 §22 and in `DECLINED.md`; the
verdict is unchanged, because it was never about the keyword.
